# 따라 말하기용 전사 연동

AI `POST /v1/transcriptions`는 기존 필드와 선택 필드 `mode`를 받습니다.

```json
{
  "audio_base64": "<녹음 파일 base64>",
  "mime_type": "audio/wav",
  "mode": "PRONUNCIATION"
}
```

- 생략 시 `DICTATION`: 기존 문장·대화 입력과 호환됩니다. 이 모드도 비단어·틀린 발음을
  사전 단어로 교정하지 않도록 지시합니다.
- `PRONUNCIATION`: 음절·반복 횟수 보존을 추가 지시합니다. 목표 단어/hint를 입력하지
  않습니다. 정답 단어로 유도하지 않기 위해 프롬프트에도 구체적인 단어 예시를 넣지 않습니다.
- 응답 계약 `{ "text": "...", "status": "ok" | "no_speech" }`는 유지합니다.

## 백엔드 전달 사항

현재 백엔드 `POST /speech/transcriptions`는 multipart `audio`, 선택 `childId`만 처리합니다.
발음 모드를 연결하려면 선택 form 필드 `mode`(기본 `DICTATION`)를 받고, `LearningAiClient.transcribe`가
AI 요청 JSON에 그 값을 전달하도록 변경해야 합니다. 프론트만 mode를 추가하면 적용되지 않습니다.
허용 값은 `DICTATION`, `PRONUNCIATION`입니다. `hint`와 정답 단어는 전달하지 마세요.

## 기능 한계와 UI 문구

Gemini의 텍스트 전사는 음소 단위 발음 평가가 아닙니다. 프롬프트를 강화해도 비단어를
익숙한 단어로 보정할 수 있습니다. 인식 문자열이 목표 단어와 같다는 사실만으로 정확한 발음을
검증했다고 표현하면 안 됩니다. '이렇게 알아들었어요', '목표 표현과 같게 인식됐어요'처럼
인식 결과를 보여 주세요. 다른 문자열일 때도 학습자의 발음 오류로 단정하지 마세요.

목표 표현과 전사문만으로 만든 발음 팁 역시 녹음의 실제 조음 오류를 진단하지 못합니다.
발음 채점이나 조음 피드백이 필요하면 원본 음성과 전문 발음 평가·음소 정렬을 별도로 검토해야 합니다.
실제 비원어민 녹음으로 전사 보정 여부를 검증하기 전에는 '들린 그대로' 보존을 보장하지 않습니다.
